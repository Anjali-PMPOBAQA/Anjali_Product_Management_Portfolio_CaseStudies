# MVP & Product Roadmap

## 1. Product Objective

The objective of the refactoring is to move from a fixed subscription package model to a configurable framework that allows business teams to create and manage different subscription offerings.

The MVP focuses on establishing the core configuration capabilities required to support regular, seasonal and promotional packages.

---

# 2. MVP Definition

### MVP Goal

Enable Business Admins to configure subscription packages through Backoffice and ensure that the configured offerings are correctly presented to customers.

### MVP Scope

| Capability                          | MVP |
| ----------------------------------- | --- |
| Create package                      | ✅   |
| Edit package                        | ✅   |
| Configure package type              | ✅   |
| Configure duration                  | ✅   |
| Configure price                     | ✅   |
| Configure promotional price         | ✅   |
| Configure benefits                  | ✅   |
| Configure expiry                    | ✅   |
| Configure priority                  | ✅   |
| Activate/deactivate package         | ✅   |
| Display active packages on frontend | ✅   |
| Display package benefits            | ✅   |
| Customer package selection          | ✅   |

---

# 3. MVP User Flow

```text
Business Admin
      ↓
Create / Edit Package
      ↓
Configure Pricing
      ↓
Configure Duration & Expiry
      ↓
Configure Benefits
      ↓
Set Priority
      ↓
Activate Package
      ↓
Frontend Display
      ↓
Customer Reviews Package
      ↓
Customer Selects Package
```

---

# 4. Prioritization Approach

The MVP prioritizes capabilities that are essential to make the configurable package model usable.

### Must Have

* Package creation
* Package editing
* Pricing
* Duration
* Benefits
* Expiry
* Priority
* Activation/deactivation
* Frontend display

### Future Enhancement

* Scheduled package activation
* Advanced promotional configuration
* Customer segmentation
* Personalization
* Package experimentation
* Advanced package analytics

The prioritization keeps the first release focused on the core business problem: **moving from fixed packages to configurable packages.**

---

# 5. Product Roadmap

## Phase 1 — Configurable Package Foundation

### Objective

Establish the core configurable package framework.

### Capabilities

* Package creation and editing
* Package type configuration
* Pricing
* Promotional pricing
* Duration
* Benefits
* Expiry
* Priority
* Activation/deactivation
* Frontend package display

### Expected Outcome

Business teams can create and manage different package offerings using the configurable framework.

---

## Phase 2 — Business Flexibility

### Objective

Expand the framework to support more dynamic business and promotional requirements.

### Potential Capabilities

* Seasonal packages
* Promotional packages
* Scheduled package activation
* Enhanced promotion configuration
* Time-bound campaigns

### Expected Outcome

Business teams can support a wider range of campaign-driven subscription offerings with less dependency on structural product changes.

---

## Phase 3 — Optimization

### Objective

Use customer and package data to improve subscription performance.

### Potential Capabilities

* Customer segmentation
* Package experimentation
* Personalization
* Package-level analytics
* Performance comparison between offerings

### Expected Outcome

The subscription model can evolve from configuration flexibility toward data-informed optimization.

---

# 6. Roadmap Principle

The roadmap follows a progressive approach:

**Foundation → Flexibility → Optimization**

The initial release solves the core configurability problem before introducing more advanced capabilities such as personalization and experimentation.

---

# 7. Scope Control

### Included in MVP

Core package configuration and customer-facing package presentation.

### Not Included in MVP

Advanced personalization, experimentation, segmentation and analytics.

These capabilities remain future opportunities so that the initial release remains focused on the primary product problem.
